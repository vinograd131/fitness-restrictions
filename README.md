# Классификатор тренировочных ограничений по анамнезу

Определяет по свободному тексту жалобы/анамнеза одну из 8 групп тренировочных ограничений,
чтобы фитнес-приложение или тренер могли адаптировать программу и снизить риск травм.

## Бизнес-задача

**Проблема.** Фитнес-приложения и онлайн-тренеры составляют программы, основываясь только на опросниках. Что болит? и т д. Проблема в том, что ограничения в таком случае выдает тренер, не имеющий медицинского образования. Есть риск подобрать неподходящий тренировочный план просто из-за незнания.

**Заказчик (ЦА).** B2B: фитнес-приложения, агрегаторы тренеров, ЛФК-сервисы. Альтернативы у них
сейчас — ручные анкеты-чеклисты, не понимающие свободный текст

**Бизнес-цели.** Снизить риск травм и возвратов из-за неподходящей нагрузки; автоматизировать
онбординг (мгновенный скрининг жалобы вместо ручного разбора анкеты).

**Инженерные задачи.** Классификатор группы ограничений по свободному тексту жалобы + REST-сервис
для интеграции.

## Группы ограничений

Позвоночник · Суставы · Кардио+невро · Дыхательные · Эндокрин/метабол · ЖКТ/брюшные ·
Мочеполовые/таз · Кожа.

Группы получены переформулировкой кодов МКБ-10 под задачу (см. `src/mapping.py`).

## Данные

RuMedTop3 из бенчмарка RuMedBench. Поля: `idx`, `symptoms`, `code`. После фильтрации —
4609 / 835 / 802 (train / dev / test). Коды без отношения к тренировкам (D50/H65/Z00/F41)
исключаются. Главная метрика — **macro-F1** (дисбаланс классов ~7×).

Сами файлы в репозитории не лежат — как их получить, написано в [data/README.md](data/README.md).

## Модели и результаты

Финальное сравнение — на отложенном **test** (804 примера, оценивается один раз). dev — для подбора гиперпараметров.

| Модель | dev macro-F1 | test macro-F1 | test accuracy |
|---|---|---|---|
| tf-idf + LogReg (лемматизация) | 0.854 | 0.868 | 0.873 |
| **RuBioRoBERTa (файнтюн, LoRA)** | 0.854 | 0.865 | 0.870 |
| CatBoost на fastText | 0.833 | 0.843 | 0.852 |
| fastText + LogReg | 0.821 | 0.832 | 0.843 |
| RuBioRoBERTa (frozen) + MLP | 0.815 | 0.820 | 0.836 |

На чистом test лемматизированный tf-idf baseline и дообученная RuBioRoBERTa идут **вровень**
(~0.87, разница в пределах шума одного прогона). Преимущество трансформера проявляется не в
среднем по test, а в **устойчивости к свободной речи** - см. следующий раздел. Поэтому в прод
выбрана RuBioRoBERTa: реальные жалобы пишут свободным языком, а не как в обучающем наборе.

## Робастность и поведенческие тесты

Тесты по методологии CheckList (Ribeiro et al., ACL 2020): INV — инвариантность к перефразу,
MFT — минимальный функциональный тест на коротких однозначных жалобах.

**INV.** Тестовые жалобы перефразированы через Mistral с сохранением смысла и меток
(`src/evaluation/robustness.py`), на перефразе не обучаюсь.

| Модель | test | перефраз | Δ |
|---|---|---|---|
| **RuBioRoBERTa (файнтюн, LoRA)** | 0.865 | **0.774** | −0.09 |
| tf-idf + LogReg | 0.868 | 0.653 | −0.21 |
| CatBoost на fastText | 0.843 | 0.591 | −0.25 |
| fastText + LogReg | 0.832 | 0.571 | −0.26 |

Ключевое наблюдение: проседают **все модели без контекстных эмбеддингов**, причём одинаково
сильно (−21…−26 п.п.), а трансформер теряет только 9 пунктов. 

**MFT.** 288 сбалансированных коротких жалоб (8 групп × 6 симптомов × 6 шаблонов, по 36 на
группу), собираются шаблонами из лексиконов в `src/evaluation/behavioral.py`.

| Модель | accuracy |
|---|---|
| fastText + LogReg | 0.847 |
| tf-idf + LogReg | 0.833 |
| RuBioRoBERTa (файнтюн, LoRA) | 0.802 |
| CatBoost на fastText | 0.792 |

На однозначных шаблонных фразах простые модели справляются не хуже чем трансформер, fastText даже лучше всех. Это ожидаемо: MFT проверяет узнавание симптома, а не разбор
свободной речи. Слабее всего у всех моделей группа КАРДИО+НЕВРО (0.44 у трансформера) — она
объединяет разнородные состояния, и это главный кандидат на разделение.

Графики: `reports/robustness.png`, `reports/behavioral.png`, `reports/mft_by_group.png`.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

python -m src.models.baseline --split dev
python -m src.models.fasttext_clf --split dev
python -m src.models.catboost_clf --split dev
pytest
```

Поведенческие тесты и графики:

```bash
python -m src.evaluation.behavioral      # MFT
python -m src.viz.plot_behavioral        # behavioral.png, mft_by_group.png
python -m src.viz.plot_robustness        # robustness.png
```

Трансформер (RuBioRoBERTa + LoRA) считается на GPU `notebooks/02_transformer_colab.ipynb`
в Google Colab. Зависимости для трансформера лежат в `requirements-transformer.txt`.

## Сервис и развёртывание

`src/serve.py` — REST API (FastAPI). Эндпоинты:
- `GET /ping`, `GET /health` — проверки живости/статуса;
- `GET /groups` — все группы и их ограничения;
- `POST /predict` — `{"text": "..."}` → `{group, restriction, confidence}`.

Модель в прод — RuBioRoBERTa (`MODEL=transformer`), лёгкий fallback на tf-idf (`MODEL=baseline`).
Запуск в Docker на CPU, GPU не требуется:

```bash
docker build -t anamnes .
docker run -p 8000:8000 anamnes   # Swagger UI: http://localhost:8000/docs
```

### Порог уверенности

Неверное ограничение в фитнесе дороже лишнего вопроса, поэтому при низкой уверенности сервис
не настаивает на ответе: помечает `needs_clarification`, просит описать жалобу подробнее и
отдаёт топ-кандидатов.

Порог подобран **на dev** (`src/evaluation/selective.py`): берём наименьший порог,
дающий нужную точность на принятых предсказаниях. Он **свой для каждой модели** — калибровка
разная: трансформер самоувереннее tf-idf.

| Модель | Порог | Покрытие | Точность принятых |
|---|---|---|---|
| RuBioRoBERTa (прод) | 0.80 | ~75% | ~94% |
| tf-idf + LogReg | 0.75 | ~74% | ~95% |

Вывод: дообученный трансформер **хуже откалиброван**, а именно уверен даже когда ошибается.
Добавляем temperature scaling.

## AI-инструменты в разработке

- **Mistral API** — для теста на робастность: перефразировка тестовых жалоб
  (`src/evaluation/robustness.py`)
- **AI-ассистент** — сверка расшифровок кодов МКБ-10 при сборке таксономии и помощь при написании
  кода. Решения по моделям, метрикам и методологии оценки подбирала сама, исходя из
  имеющихся данных и целей.

## Структура

```
src/
├── config.py           
├── mapping.py          группа, ограничения
├── data.py            
├── models/
│   ├── base.py        BaseClassifier — общий интерфейс всех моделей
│   ├── baseline.py    tf-idf + LogReg 
│   ├── fasttext_clf.py, catboost_clf.py
│   └── transformer_frozen.py, transformer_ft.py   RuBioRoBERTa (frozen / LoRA)
├── evaluation/        метрики, поведенческие тесты, робастность, кривая обучения
├── viz/               графики
└── serve.py           FastAPI
notebooks/   EDA и Colab-ноутбуки
tests/       pytest
reports/     графики и метрики
scripts/     черновик маппинга кодов МКБ
data/        README: откуда взять данные
models/      LoRA-адаптер прод-модели
Dockerfile   CPU-образ сервиса
```

Все модели реализуют `BaseClassifier` (`predict_proba` + `classes`), поэтому оценка и сервис
работают с любой из них одинаково и не знают, что внутри — tf-idf или трансформер.
